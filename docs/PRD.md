# PRD: mac-agent-machine

Mac 한 대(MacBook 또는 Mac mini)를 팀의 "에이전트 코딩 서버"로 만든다. 여러 사용자가 외부에서 각자 격리된 macOS 계정으로 접속해 Claude Code와 Codex로 코딩한다. 접속 수단은 SSH, iOS 앱, 웹 대시보드 세 가지다.

## 1. 배경과 목표

- 노트북이 없어도 폰에서 에이전트에게 작업을 시키고, 진행 상황을 보고, 권한 요청에 답하고, 결과 파일을 확인할 수 있어야 한다.
- 터미널 화면을 폰에 그대로 옮기는 방식은 배제한다. 에이전트가 내보내는 구조화 이벤트(메시지, 도구 호출, diff, 권한 요청)를 카드 UI로 보여준다.
- 사용자마다 자기 Claude/OpenAI 구독으로 로그인한다. 서버 주인의 API 키를 공유하지 않는다.
- 공유기 포트 개방 없이 Tailscale 사설망 안에서만 노출한다.

## 2. 사용자

| 역할 | 인원 | 하는 일 |
|---|---|---|
| 서버 관리자 | 1명 | Mac 소유자. 설치 스크립트 실행, 사용자 계정 생성, Tailscale 초대 |
| 사용자 | 2~10명 | 노트북에서 SSH, 이동 중 iPhone 앱, 데스크톱 브라우저에서 웹 대시보드 |

## 3. 핵심 시나리오

1. 관리자가 `scripts/setup-server.sh`를 실행한다. Tailscale, sshd 강화, gateway 데몬(launchd)이 설치된다.
2. 관리자가 `mam user add alice --email alice@example.com --ssh-key "ssh-ed25519 ..."`를 실행한다. macOS 계정, 이메일 매핑, 워크스페이스 디렉토리, authorized_keys가 만들어진다.
3. alice는 Tailscale 초대를 수락하고 `ssh alice@macmini`로 접속해 `claude login`, `codex login`을 1회 수행한다. 앱에서 로그인 URL을 받아 처리하는 흐름도 제공한다.
4. alice가 iPhone 앱에 서버 주소를 입력한다. Tailscale 신원으로 자동 인증된다. 프로젝트 디렉토리를 고르고 Claude 세션을 만든다. 지시를 보내면 에이전트의 진행 상황이 카드로 흘러나온다. 권한 요청이 오면 승인/거절한다. 파일 브라우저에서 변경된 파일과 diff를 확인한다.
5. alice가 데스크톱 브라우저에서 같은 세션에 붙어 이어서 작업한다. 폰과 웹이 같은 이벤트를 동시에 본다.

## 4. 기능 요구사항

MVP는 Phase 0(서버)과 Phase 1(iOS 앱)이다.

| ID | 요구사항 | Phase |
|---|---|---|
| F1 | 외부 접속은 Tailscale 전용. 포트 개방 없음. SSH는 공개키 인증만 허용 | 0 |
| F2 | 사용자 격리는 macOS 계정 단위. 에이전트 프로세스는 해당 계정 권한으로 실행. 파일 API는 홈 디렉토리 밖 접근 불가 | 0 |
| F3 | 앱/웹 인증은 Tailscale whois로 얻은 로그인 이메일을 macOS 계정에 매핑. 비밀번호 없음 | 0 |
| F4 | Claude Code(Agent SDK)와 Codex(app-server)를 공통 이벤트 모델로 정규화해 지원 | 0 |
| F5 | 세션 생성/목록/재개/중단/닫기. 여러 클라이언트가 같은 세션에 동시 접속. 재접속 시 놓친 이벤트 재생 | 0 |
| F6 | 명령 실행, 파일 변경, 권한, 사용자 입력 요청을 앱에서 승인/거절. "이 세션에서 항상 허용" 지원 | 0, 1 |
| F7 | 현재 작업 디렉토리 파일 트리, git 상태 배지, 파일 뷰어(문법 하이라이트), diff 보기 | 0, 1 |
| F8 | 앱에서 Claude/Codex 로그인 시작 → URL 표시 → 코드 입력으로 완료 | 0, 1 |
| F9 | iOS 17 이상, SwiftUI, iPhone 우선. iPad는 분할 레이아웃 | 1 |
| F10 | 웹 대시보드. gateway가 정적 파일로 서빙 | 5 |
| F11 | 세션 모드 전환(ask / auto-edit / full-auto / plan) | 0, 1 |
| F12 | 관리자 CLI: 사용자 추가/목록/삭제, 진단(`mam doctor`) | 0 |
| F13 | 세션 화면에서 파일 목록을 "대화 \| 파일" 세그먼트로 즉시 전환. 변경 파일 수 배지 | 2 |
| F14 | 작업 디렉토리 선택 시 홈에서 폴더 탐색 + 새 폴더 생성(`POST /fs/mkdir`) | 2 |
| F15 | 세션 컨텍스트 사용률, 누적 토큰·비용, 모델·사고 수준 표시와 변경, 구독 사용 한도(Claude 5시간/주간, Codex 창) 표시 | 2 |
| F16 | 에이전트 팀(Phase 3): 한 프로젝트에 역할별 팀원(Claude/Codex 혼합)을 꾸리고 그룹방·DM 에서 `@멘션`으로 지시. 팀원은 각자 git worktree 에서 일하고 서버가 턴 종료 시 커밋, 사용자가 방에서 머지 승인. 승인 요청은 방에 미러링. 서버는 Phase 3, iOS 화면은 Phase 4 | 3, 4 |

Phase 번호(2026-09-12 조정): 0 서버, 1 iOS 앱, 2 사용량·파일(F13~F15), 3 에이전트 팀(서버), 4 에이전트 팀(iOS), 5 웹 대시보드, 6 운영(TestFlight/APNs 등).

## 5. 비기능 요구사항

- 보안: gateway의 특권(root) 코드는 접속 수락, 신원 조회, 사용자 프로세스 생성, 프록시로 한정한다. 사용자 입력 문자열을 셸로 실행하지 않는다.
- 안정성: 데몬은 launchd가 자동 재시작한다. 에이전트 프로세스가 죽으면 세션은 error 상태가 되고 네이티브 세션 ID로 재개 가능해야 한다.
- 지연: 에이전트 이벤트가 앱에 도달하기까지 tailnet 기준 200ms 이내. 권한 요청은 1초 이내 표시.
- 자원: 세션당 메모리 이벤트 버퍼 상한을 두고, 초과분은 디스크 로그에서 재생한다. 유휴 세션의 에이전트 프로세스는 일정 시간 후 종료하고 재개 가능 상태로 둔다.
- 운영: 설정 파일 하나(`/etc/mam/config.json`)와 `mam doctor` 한 번으로 상태를 파악할 수 있어야 한다.

## 6. 범위 밖 (v1)

- App Store 배포, TestFlight, APNs 푸시. 유료 개발자 계정이 필요하므로 Phase 6에서 다룬다.
- 터미널 에뮬레이션. 필요해지면 Phase 6에서 fallback으로 검토한다.
- Linux/Windows 서버, Docker 격리.
- 사용자 간 세션 공유나 협업 편집.
- 서버 주인 API 키 공유 모드.
- 에이전트 팀의 worktree 의존성 자동 설치(`npm ci` 등), 자동 머지(사용자 승인 없는 머지), 팀원 답변의 실시간 스트리밍(v1 은 턴 종료 후 한 번에 게시).

## 7. 성공 기준

- 신규 사용자 온보딩이 관리자 명령 1개와 사용자 로그인 2회로 끝나고 10분 이내에 완료된다.
- 폰에서 세션을 시작해 첫 이벤트를 받기까지 에이전트 자체 지연을 제외하고 3초 이내다.
- 권한 요청이 발생한 뒤 1초 이내에 앱에 표시되고, 응답이 에이전트에 전달된다.
- 폰과 웹이 같은 세션의 같은 이벤트를 순서대로 본다.
- 한 사용자가 다른 사용자의 홈 디렉토리나 세션에 어떤 API로도 접근할 수 없다.
